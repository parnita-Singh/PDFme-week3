## Project layout

- Used `C:\Users\asus\PDFme` because that folder already existed in the home directory.

## Inventory (foundation for later phases)
- Effective DPI for a placed image is pixels / (placed size in inches), with placed size taken from the CTM at each `Do`. `effective_dpi` is `max(dpi_x, dpi_y)` so anisotropic placements still trigger downsampling if either axis is above the cap. The sample banner is 352.94 dpi on X and 354.55 dpi on Y because 3000×3900 pixels on a 612×792 pt page is not perfectly square pixels.
- If the same image is drawn more than once on a page, DPI is computed from the **largest** placement (lowest DPI). Downsampling from a tiny high-DPI drawing would destroy a large drawing of the same XObject.
- Form XObjects are walked so images nested in Canva-style forms are still listed.
- Inline images (`BI`/`ID`/`EI`) are not inventoried in Phase 1. They are uncommon in Canva exports; adding them later would need a different replacement path.

## Compression
- Only images whose effective DPI is **above** `max_dpi` are rewritten. Equal-to-cap images stay byte-for-byte the same object.
- Target pixel size is `round(px * max_dpi / effective_dpi)`, then clamped so it never exceeds the original (never upscale).
- Resampling is Pillow `LANCZOS`.
- Colour images become JPEG (`DCTDecode`) at the requested quality. Soft masks stay **Flate** grayscale, never JPEG, so alpha stays lossless.
- JPEG quality is clamped to 1–95 because Pillow's JPEG encoder is specified up to 95.
- Indexed (`/Indexed`) images that we downsample are converted to RGB JPEG (JPEG has no palette mode). Recorded here because the prompt forbids RGB↔CMYK conversion, not palette flattening required by JPEG.
- ICC-based images that Pillow decodes to RGB/CMYK/L are re-embedded as the matching Device colour space after JPEG encode. Preserving the original ICC stream on a JPEG of possibly different decoding is unreliable; Device* matches the pixels we actually encoded.
- `/DecodeParms` is deleted after rewriting because DCTDecode parms from the old filter (or Flate predictors) would be stale.
- `/Decode` on the image is left as-is when present (some CMYK JPEGs rely on inverted Decode arrays). New JPEGs written from Pillow do not add a Decode array.
- pikepdf save uses object streams, stream compression, Flate recompress, and `remove_unreferenced_resources()` when available.
- Reports are always written as JSON plus a sibling `.txt` summary. If `--report` is omitted, the default is `<output>.report.json`.

## Sample PDF
- `samples/test_banner.pdf` is generated by `make_sample.py`: US Letter, JPEG RGB full-page 3000×3900 (~353 dpi) banner and a 576×576 image placed at 144 pt (~288 dpi). Fine noise is mixed into the banner so the full-resolution JPEG is larger than a 150 dpi recompress (smooth Canva-style fills compress too well as Flate and can grow when turned into JPEG).

## Runtime
- Development Python on this machine is 3.14 (via `py -3`). The project requires 3.11+; 3.14 is accepted.
- Each image object is rewritten once. Its target DPI is the highest effective DPI it is drawn at, so it fits every page it appears on.
- Colour spaces are kept where possible: DeviceRGB/Gray/CMYK and ICCBased. Indexed (RGB base) is converted to RGB and recorded. Stencil masks, spot colours and other spaces are left unchanged and reported as not_rewritten.
- /Decode and /DecodeParms are removed when an image is re-encoded, because the new pixels already have the decode applied.
- The silent RGB fallback is removed. Failures are recorded as skipped, with a warning, and make ok false.
- Soft masks are always written as new objects, so a mask shared with another image is never changed by accident.
- Placements are matched by image object number, not by name. Forms drawn more than once record every placement. Self-drawing forms are skipped.
- Inline images and images inside patterns are reported with a note and not rewritten.
- The saved file is checked: if any image is still above max_dpi, a warning is added.

- Gemma labels pages, it does not edit them. Labels: banner_background, subject_photo, logo, text_page, keep_as_is. Background removal runs on subject_photo and logo pages only.
- A reply that cannot be read, or a label outside the list, is recorded as keep_as_is with the reason, and nothing on that page changes.
- If a Gemma call fails, the page is kept as is and the failure is in the report.
- If Ollama is not running, the classifier is skipped with a message and the default background rule is used.
- The page is rendered at about 1000 px wide and sent as a PNG, with temperature 0 so the answer is repeatable.
- The model name is a setting (--gemma-model). Default: gemma3:4b.
